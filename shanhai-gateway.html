01 / 为什么

它为什么长这样

先交代来历。这不是论文落地，是被免费池和账单逼出来的。

外国人开了个不限量的免费模型，中国人就去薅：注册一堆号，自己薅够了转手卖给别人薅， 薅到厂商受不了，免费就没了。

我干的是同一个路子，区别有两条：我免费教你怎么薅；而且我不白嫖——每个月拿一百多块养着场子， 商业通道、代金券、免费池混着走，该付的付掉，剩下的让免费池扛。 10 月这波实测，月 200 亿 token 的现金账单压到了 ¥170。

代价是毛病一堆。下面这些坑我全踩过，一个坑换回来一条规则，全记在运维语义表里。 山海关就是这么长出来的：把各路免费池、代金券和按量套餐拧成一个稳定的上游池。

02 / 特性

它做什么

核心就一句话：让不靠谱的上游一起干靠谱的活。剩下的都是为这句话服务的。

FEAT-01

SWRR 加权轮转 + 兜底链隔离

权重、并发、超时逐后端可调。兜底后端与主力池隔离，互不污染。

FEAT-02

错误分类学驱动的冷却

403/429 指数退避 5m→10m→…→4h 封顶；满载排队 60s 而不是甩 503；客户端断连不吃冷却。

FEAT-03

任务级会话亲和

优先 X-Job-Id、退回 X-Session-Key，同一任务钉回同一后端。实测前缀缓存命中率 27% → 51%，峰值 69%。

FEAT-04

quirk 怪癖层

某家专属的报错体/用量键写进独立包，内核零按名分支。没怪癖的上游零配置。

FEAT-05

多用户下游 key 计费

sk-user-* 额度核发 + 可插拔登录（注册表模式）+ 公版用户中心。

FEAT-06

影子留存观测

SQLite 单库存 attempts/captures，落库前自动脱敏，/api/stats 细粒度看板。

FEAT-07

额度窗探针 + 自动摘除

按后端名查每家的 5h/7d/30d 额度窗，sidecar 每 60s 判一次：窗打满就摘，回落后再开回来。加订阅不改任何映射表。

FEAT-08

sidecar 慢周期自愈

独立 Python 进程，纯标准库零依赖。按窗口增量失败率做限流/降级，与网关快路径分工。

FEAT-09

Docker 一把梭

多阶段构建、非 root 运行、自带 healthcheck，镜像内零密钥。

    05 / 运维语义

    事故沉淀的规则表

    要把它钉进产线或者魔改路由，先读这里的「为什么」。每个魔法数字都有事故出处。

    01

    客户端断连不冷却

    +
    10-03 一次断连风暴打出 1720×503：客户端断开被记进后端失败 → 正常后端挨个进冷却 → 全网无后端可用。断连只能归为 network 类观测，不吃冷却、不踩熔断。
    02

    模型不存在是后端的锅

    +
    上游悄悄下架 model 时网关表现为 4xx/黑洞，某兜底后端曾 0 成功率空转 4 天半才被发现。这类 4xx 不能归给客户端，要落在对应后端头上走冷却/摘除，身份走 model_expire / model_fallback 打补丁。
    03

    配额类走指数退避，满载走排队

    +
    403/429 指数冷却 5m→10m→…→4h 封顶，不反复白撞；满载不降级，排队到 60s（QUEUE_WAIT）再给答案，而不是直接扔 503。
    04

    黑名单只写不删，须人工清理

    +
    backends.blocked.json 是启动自检判定的「永久失效」清单，没有自动解除路径——自动复白会用失败率当证据，而黑名单的判断依据是探测事实。摘条目必须人工复核后从文件里删。
    05

    strike 只在成功时清零，勿乱改

    +
    10-01 的 403 自锁风暴：配额没恢复就清零 strike → 后端带着空鼓回池子 → 立刻再 403 → 冷却重启 → 循环打。指数退避的整条链依赖「连续击中数只靠成功归零」，admin 热改不提供 strike 入口是设计，不是缺失。
    06

    会话亲和 = 轮转外一层「优先选择」

    +
    10-10 实测前缀缓存命中率 0%：SWRR 把同一对话轮流甩给不同 provider，前缀缓存在 provider 侧，换家就凉。亲和键优先 X-Job-Id（任务级，正是前缀缓存的复用单元），退回 X-Session-Key。只有最终成功且内容已交付才写表，防失败会话钉死在坏后端；逐出/保持判定与冷却/熔断同源，不发明第二层健康层。
    07

    按家怪癖进 quirk 层，内核零名字分支

    +
    揉进通用规则会伤别家，加 if name==xxx 会把名字判定撒进内核，两条都是错路。「只在某家出现的问题」写进 internal/core/quirk/xxx.go，内核只在出口装饰 / 错误分类 / 用量解析三个固定缝上查表。怪癖是数据（配置字段），不是代码分支。
    08

    观测契约对齐 SLR 同形

    +
    attempts 表含 job_id 列（对已存在库幂等 ALTER 迁移）；/api/stats 提供同形 affinity{hits,misses,puts,pinned_jobs} 对象。按 job 归因的脚本迁移后原样可用。
    06 / 排查

    故障排查

    都是实际被问过的。

    网关起不来，报「没有后端配置」
    env 指错目录。GATEWAY_CONFIG_DIR 必须包含 backends.json；docker 场景检查挂载卷 runtime/config/ 是否真的有文件（docker logs shg 看启动段解析了几个后端）。
    某个后端一直不被选中
    GET /api/stats 看三个字段：enabled（配置里被关）、cooldown_remain_s（配额类冷却中，最长 4h）、circuit_open。注意 circuit_open:false 不代表没冷却，两者是两套计数。
    全部后端都在冷却，请求全挂
    这正是规则 #1 要防的形态。检查 fail_breakdown：大量 network 类失败多半是客户端断连风暴误伤（老版本语义），确认你在跑当前版本；如果是 401 集中爆发，是 key 失效，换 key 前冷却不会自己好。
    看板有数据，想看原始请求
    查 SQLite captures 表（先读仓库里的 captures 消费契约）。落库前已经过 scrub 脱敏（密钥/内网路径/手机号/Bearer 头 → [mask]），这是特性不是缺陷。
    docker 容器反复重启
    docker logs shg 看退出原因；大概率是 runtime/config/ 缺文件或 JSON 不合法。healthcheck 连续失败会让编排层标记 unhealthy，但 restart: unless-stopped 只看进程退出。
